# ct-fsguard 核心需求（用户视角）

> 状态：只读回顾，基线 `46e7196`。依据 `docs/requirements.md`（R-01…R-17）、`docs/proposal.md`、`docs/analysis.md`、`README.md`，缺口编号沿用 [需求盘点](reviews/fsguard-requirements-audit.md)。
> 本文按"用户拿这个包做什么"重组，不改原条目；原文与判据仍以 `requirements.md` 为准。

## 0 一句话结论

ct-fsguard 想在 `std::fs` 之上补四件事：**按路径做词法准入判断**、**在受限根/前缀/黑名单下读写**、**按 offset 分块读**、**带深度和回调的受控遍历**，外加结构化错误码。它**不解决安全隔离**：不解析符号链接、不防 TOCTOU、不防硬链接/挂载点/超长路径，也不做线程安全、原子写、Win32（`README.md:6`；`requirements.md:297`、`:358`、`:153`）。用户应把它当"策略层 + 便利层"，不是安全边界（D-012）。

## 1 七个能力面

### 面 1 路径准入与越界防护

- **管什么**：判断"这个路径在不在允许范围内"。纯词法，不 `stat`、不 `realpath`；顺序冻结为 规范化 → `_root` 段边界 → `_allow_prefix` → `_deny_pattern` → `FS_OK`（`requirements.md:161`）。
- **对应**：R-05、R-06、R-09、R-10。
- **关键期望值**：
  - 规范化：`src/../a.c`→`a.c`、`./a`→`a`、`a//b`→`a/b`、`a/b/`→`a/b`、`/`→`/`、`../etc` 不变、`/../etc`→`/etc`、`/tmp/../../../etc`→`/etc`、空串→`.`（`requirements.md:90-101`）。
  - `is_under` 按段边界且包含相等：`/workspace/src` 是自身的子路径，`/workspace/src2` 不是（`:115-120`）。
  - `check`：root/allow 越界 `FS_ERR_OUT_OF_BOUNDS`；deny 命中 `FS_ERR_DENIED_PATTERN`；两者同时成立先报越界（`:161-167`）。
  - `check` 不访问文件系统：不存在的路径也返回 `FS_OK`；`FS_ERR_NOT_FOUND` 只由读写/遍历产生（`:166`）。
  - 失败时 `last_error().path` 是规范化后的路径、`message` 非空（`:168`）。
- **状态：待定**。Q-3（`..` 规则）、Q-6（绝对 root + 相对输入）、Q-7（deny glob 方言）未确认。
- **定不下来会怎样**：同一输入可能有多种"正确"规范化结果；相对路径可能被拒绝也可能按 root 解析；deny 的 `*` 是否跨 `/`、是否匹配目录都会变，相关断言无法冻结。

### 面 2 受限读写与错误可观测

- **管什么**：`FsGuard` 的 `read_file` / `write_file` / `read_chunk` 先做策略判定，再做 I/O；把 `errno` 映射成 10 个错误码；用 `FsError{code, path, message}` 暴露原因（`requirements.md:205-219`、`:237-249`）。
- **对应**：R-02、R-08、R-11、R-12、R-14。
- **关键期望值**：
  - `read_file` 的 `cap` 含 NUL：文件 `cap-1` 字节成功，`cap` 字节失败并返回 `FS_ERR_BUFFER_TOO_SMALL`；失败不写半截（`:209-210`）。
  - `write_file` 二进制安全（含内嵌 NUL）；越界返回 -1 + `FS_ERR_OUT_OF_BOUNDS` 且不创建目标文件（`:211-212`）。
  - 错误映射：`ENOENT`/`ENOTDIR`→`NOT_FOUND`；`EACCES`/`EPERM`→`PERMISSION`；`EISDIR`→`IS_DIR`；其余→`IO`（`:213`、`:242`）。
  - 越界先于 I/O：越界且不存在的路径返回 `OUT_OF_BOUNDS`，不是 `NOT_FOUND`（`:214`）。
  - `last_error()` 是只读借用，下一次 `FsGuard` 操作后失效；`clear_error()` 释放并置 NULL（`:192-198`）。
  - 显式 `impl Drop` 释放 `_root`、`_allow_prefix`、`_deny_pattern`、`_last_error.path/message`；工厂返回值用 `delete`，不用 `own`（`:150-151`）。
- **状态：已定**（判据可执行）。Q-2（`write_file` 失败是否留半截）、Q-5（非法参数错误码）只影响失败细节，不改变上述期望值。
- **定不下来会怎样**：失败后的文件状态仍不可断言；非法参数可能只能看到 -1，无法区分"参数错"还是"IO 错"。

### 面 3 大文件分块读

- **管什么**：按 offset 读固定长度，不把大文件一次性读入；每次重新打开，不做句柄缓存（`proposal.md:132-137`）。
- **对应**：R-04、R-14。
- **关键期望值**：300 字节夹具（内容 0..299）上，`read_chunk(0,buf,100)`→100 且字节相等，`(100,...)`→100，`offset==300`→0，`offset>300`→0，负 offset→-1；含内嵌 NUL 的二进制逐字节相等、不截断、不自动补 NUL；公开偏移用 `long long`/`int64_t`，不出现 `long`（`requirements.md:74-80`、`:245`）。
- **状态：已定**。Q-5 只决定负 offset 的错误码分类，不改变"返回 -1"。
- **定不下来会怎样**：调用方仍能判断失败，但无法把"参数非法"与"IO 错误"分开。
- **注意**：`char *` 原语只返回 -1，没有 `last_error`；要分类必须走 `FsGuard` 包装（`analysis.md:38`）。

### 面 4 受控遍历

- **管什么**：递归列目录，先回调 root，再按 `max_depth` 下钻；每个子项过策略；回调可中断；entry 只在本次回调内有效（`proposal.md:139-145`、`:153-159`）。
- **对应**：R-07、R-13。
- **关键期望值**：
  - 固定树回调收集 `(path, is_dir)`，排序后集合相等，不只比次数；root 回调一次且 `is_dir==1`（`requirements.md:131-132`）。
  - `max_depth=0` 只回调 root；`max_depth=1` 回调 root + 直接子项（`:133`）。
  - 回调返回 7 → `walk` 返回 7，之后回调次数为 0；root 回调返回非 0 也立即中断并返回原值（`:134`）。
  - 20 层深树在 `max_depth=16` 下不越界、不栈溢出（`:135`）。
  - deny 目录整棵子树 0 次回调；不可读子目录按 fail-closed 中断，返回 -1 + `FS_ERR_PERMISSION`（`:225-228`）。
  - 两个宿主版本共用同一份目录递归实现（`:227`、`:232`）。
- **状态：已定（`FsGuard::walk` 形态）**。Q-4 未确认的是 `char *::walk` 是否增加 `max_depth` 参数。
- **定不下来会怎样**：若 `char *::walk` 保持两参数，深度限制只能落在 `FsGuard` 一侧，无状态原语写不出"`max_depth=0` 只回调 root"的用例，R-07 判据 3 要删。

### 面 5 失败策略与部分成功

- **管什么**：失败时是继续、跳过还是中断；失败后已产生的副作用怎么表达。
- **对应**：R-09、R-11、R-12、R-13。
- **已有口径**：
  - `check` 返回非 0 时由调用方停止；包装层 `read_file`/`write_file` 内部先 `check`，越界不落 I/O（`requirements.md:214`）。
  - 遍历遇到不可读子目录显式 fail-closed：中断并返回 `FS_ERR_PERMISSION`（`:228`）。
  - 每次公开操作开始清错；成功后可观测为无错（`:194`、`:332`）。
  - `read_file` 失败不写半截缓冲区（`:210`）。
- **状态：待定**。Q-2（`write_file` 失败是否允许半截文件）未确认；全局没有"fail-open / fail-closed"契约（盘点 CG-07）；部分成功没有 API 表达（CG-08）。
- **定不下来会怎样**：`write_file` 失败后磁盘状态不可断言；`walk` 遇到 `list` 失败、读写失败时是跳是停没有统一口径，不同实现可以都"符合需求"但行为不同。

### 面 6 并发、竞态与安全边界

- **管什么**：**明确不管**。`FsGuard` 不做线程安全（`requirements.md:153`）；`check` 是词法判定，不解析链接、不 `openat`（`:170`、`:297`）。
- **对应**：R-08（非目标）、R-09（词法）、R-16（不替代 `std::fs`）。
- **关键事实**：
  - `check` 通过后到实际 `open` 之间，路径可被替换；`read_file` 会跟随符号链接。`/workspace/src/evil -> /etc` 可通过 `check` 后读到 `/etc/passwd`（`analysis.md:35`；盘点 CG-02）。
  - 硬链接、挂载点/绑定挂载、超长路径均未覆盖（CG-04/05/06）；符号链接环未明文（CG-03）。
  - 两个线程共享一个 `FsGuard` 时，`last_error` 会被互相覆盖，重入行为未定义（CG-09）。
  - macOS 上 APFS 默认大小写不敏感，而 deny 匹配要求大小写敏感；该差异未讨论（CG-10）。
- **状态：未定义（明确不做）**。这不是"待实现"，是当前边界。
- **定不下来会怎样**：任何把 `check` 当安全边界的用法都不成立；并发共享对象的结果不可复现。

### 面 7 包形态、命名共存与平台

- **管什么**：包能否以合法 CT 形态编译、与 `std::fs`/`std::str` 共存、只做 POSIX、且可被门禁验收。
- **对应**：R-01、R-03、R-15、R-16、R-17。
- **关键期望值**：
  - `pub trait` + `map trait … for type char *`；方法体放 `.shim.h`；`FsWalkCb` 放 `.h.ct`；包内 `#define` 计数为 0（`requirements.md:33-37`）。
  - 四个新方法名与 `char *` 上已有 22 个 std 方法名交集为空；同名冲突时用 `Trait::method(...)` 限定调用（`:59-63`、`:320`）。
  - MVP 只接受 `/`；`a\b` 按字面字符处理；不建 Win32 分支（`:254-258`）。
  - `std::fs` 零改动；不暴露 `exists`/`readFile`/`writeFile`/`list` 同名方法（`:266-269`）。
  - 夹具运行时生成；至少一个示例入门禁；ASan/LSan 覆盖所有权用例（`:278-283`）。
- **状态：已定**。语言依赖 0 硬阻塞、0 软阻塞（`:15`、`:39`、`:52`、`:138`、`:154`、`:217`、`:259`）；但证据指向外部 ct-lang 仓库，本仓无法复核（CG-16），门禁脚本也尚未建立（`AGENTS.md:266`）。
- **定不下来会怎样**：包形态若再改，所有签名与示例都要重写；门禁未建则上述期望值都无法自动验收。
