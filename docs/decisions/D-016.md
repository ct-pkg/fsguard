## 裁的是什么

`~/.ct/pkg/ct/std/0.3.1` 的 `ct.pkg` 写 `publisher = ct`、`version = 0.3.1`、GPL 许可；现行可消费的是 `~/.ct/pkg/std/std/0.3.2`（`publisher = std`、MIT）。旧条目与索引摘要不符，任何 `std@0.3.1` 解析都会被它挡住。要决定：删除、原地保留，还是挪走留记录。

## 事实

```console
$ ct get std@0.3.1
ctc: store '/Users/samxx/.ct/pkg/ct/std/0.3.1' already exists with a different digest
$ grep '^dep' ~/.ct/pkg/*/*/*/ct.pkg
（无命中）
```

- 条目内容：71 个文件；逐文件 sha256 排序后再 sha256 = `aae37735fdec2a5ce03595bb52a7c74f90bfcb379d162aa512a33d6608ca820c`。
- 归档摘要：`tar -cf - -C ~/.ct/pkg/ct/std 0.3.1 | shasum -a 256` = `531eacb857d2bf4209e62ee4b00ceb79ab717a6c322b5f2eb8e0f19c3335425e`。
- 没有已安装包依赖该条目，挪走不破坏消费者。

## 两席意见

| 席 | 主张 | 代价 |
| --- | --- | --- |
| proposer（PKG） | 挪到备份目录并留记录 | 需要一处迁移记录与回退命令 |
| opposition（CLEAN） | 直接删除 | 不可回退；违反「不要直接删」的约束 |

## 裁定

选 **B，已执行**：

- 原路径 → `/Users/samxx/.ct/pkg-backup/20261116/ct/std/0.3.1`；`~/.ct/pkg/ct/std/` 已空并移除。
- 记录：备份目录 `MIGRATION.md`（含回退命令）+ 本仓 `docs/reviews/fsguard-pkg-store-migration.md`（含摘要与迁移后实测）。
- `~/.ct/pkg/std/std/0.3.2` 未动；迁移后 `ct install` rc=0、`ct verify` 通过。

## 判据

1. `~/.ct/pkg/ct/std/0.3.1` 不存在；`~/.ct/pkg-backup/20261116/ct/std/0.3.1` 存在且文件数仍为 71。
2. 备份目录与本仓各有一份记录，含原路径、新路径、两个摘要与回退命令。
3. 迁移后 `ct install` rc=0、`ct verify` rc=0、`bash tools/check.sh g3-ph04 r03` rc=0。
4. 未删除任何已推送的 tag，未改写历史。

## 理由

1. **可回退**：该条目是旧发布身份的产物，未来若要复现 `std@0.3.1` 的旧行为，备份是唯一凭据；删除不可逆。
2. **消除解析阻塞**：只挪走不删除，既让包根恢复一致，又保住证据。
3. **成本可控**：一条记录 + 一个目录，不引入仓库内文件。

## 代价

- 备份目录需要人记得；记录写清「保留到何时由负责人决定」。

## 若选另一案会打破什么

- 选 A（删除）：违反本轮「不要直接删」的约束，且丢掉旧发布身份的现场。
- 选 C（原地保留）：`std@0.3.1` 永远解析失败，后续排障会重复踩同一个坑。
