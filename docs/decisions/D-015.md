## 裁的是什么

`ct install` 对只 import `.m.ct` 的消费者报错。要决定：是等上游修复，还是把门禁的验收信号换成 `ct build` 并把 install 的红色单独立案。

## 事实

消费者 `/tmp/fsg-install-probe`（`dep = std@0.3.2`，`main.ct` 只有 `import std::fs::Fs;`）：

```console
$ ct install
ctc: 'main.ct' cannot resolve import 'std/fs/Fs'
INSTALL_RC=1
$ ct build main.ct -o probe
'cc' -std=c99 -I '/Users/samxx/.ct/pkg/std/std/0.3.2/std/fs' -I '.ctbuild' '.ctbuild/main.c' '-o' 'probe'
BUILD_RC=0
$ ./probe; echo $?
0
```

上游根因：`Pkg.h.ct:1609-1618` 的 import 校验只 stat `<rel>.h.ct` 与 `<rel>.ct`，漏 `<rel>.m.ct`。`PKG-6`（install 不校验 import）仍 open，本条是「校验存在但漏一种单元」。

## 两席意见

| 席 | 主张 | 代价 |
| --- | --- | --- |
| proposer（PKG） | 门禁验收 = `ct build` + 运行；install 缺陷登记 | install 红色长期存在，需要 issue 跟踪 |
| opposition（WAIT-UPSTREAM） | 等 ct-lang 修好 `.m.ct` 再验收 | `.m.ct` 是 std 映射单元的唯一形态，等修等于把 R-03 无限期挂起 |

## 裁定

选 **B**：

- R-03 的验收命令与门禁一律用 `ct build` + 运行断言；`ct install` 的 rc 不作为通过依据（PKG-6 已说明它不校验 import）。
- `ct install` 的 `.m.ct` 缺陷登记 `issues/FSG-02.md`，附原文、上游锚点与关闭条件。
- 不修改 ct-lang、不 vendor 源码、不在门禁里自己推导包含根。

## 判据

1. `bash tools/check.sh g3-ph04 r03` rc=0，且该子门禁的构建命令是 `ct build`（不是 `ct install`）。
2. `issues/FSG-02.md` 含 `ctc: 'main.ct' cannot resolve import 'std/fs/Fs'` 原文与 `Pkg.h.ct:1609-1618` 锚点。
3. 门禁里没有出现「用 install rc=0 证明 import 可解析」的断言。
4. 消费者工程只靠 `dep` + `ct.lock`（无 `vendor/`）即可 `ct build` 并运行。

## 理由

1. **验收要证明的是「消费者装上就能 build 并运行」**，不是「install 的 rc 是 0」。install 的职责是校验 store 并打印建议命令，PKG-6 已说明它不校验 import。
2. **等上游没有可执行的触发条件**：该缺陷无 issue 编号外的排期信息；把 R-03 挂在一个没有日期的上游修复上，等于重复 D-013 之前的问题。
3. **C（门禁自算 `-I`）会掩盖安装根是否真的对**：v0.62.0 的 `ct build` 已按 lock 自动补根，自算是多余且偏离消费者路径。

## 代价

- `ct install` 在 `.m.ct` 消费者上仍会红，需要读者知道 FSG-02。
- 门禁与 install 的行为不一致，需在卡面与证据里写清原因。

## 若选另一案会打破什么

- 选 A（等上游）：R-03 判据 1/2 无期限挂起，PH-04 收口被一个无排期的上游缺陷绑架；且无法证明「装上就能 build」。
- 选 C（自算包含根）：门禁绿了，但测试与消费者的包含根来源不同，属于把主张偷换成「我们自己会算」。

## 残留风险

| # | 风险 | 处置 |
| --- | --- | --- |
| K-1 | 上游修复后 install 变绿，门禁仍只用 build | 修复后可在 FSG-02 追加一条 install 冒烟，不改变主验收 |
| K-2 | 有人只看 `ct install` rc 宣布可用 | FSG-02 与卡面均写明「install rc=0 ≠ import 可解析」 |

## 失效条件

- 上游修复 `.m.ct` 的 import 校验（`Pkg.h.ct` 增加 `%s.m.ct` 分支）且发布：FSG-02 关闭，可把 install 冒烟加回门禁作为附加证据（主验收仍是 build + 运行）。
