## 裁的是什么

R-05 判据 4 原文写「`out` 与输入重叠（`out == path`）被文档禁止，README 写明该限制；**实现不负责检测**」。roadmap PH-01 又把 FSR-16「检测重叠并返回 -1」列为整改项。同一条判据与整改项互相矛盾。

## 两案对比

| 案 | 行为 | 代价 | 与既有条款的关系 |
| --- | --- | --- | --- |
| A（推荐） | 实现检测重叠（`out == path` 或缓冲区相交），命中返回 -1 并把 `out[0]` 置 0；README 仍写明该调用是错误用法 | 每次调用多两次指针范围比较 | 与 FSR-16 一致；把判据 4 的「不负责检测」改成「必须拒绝」 |
| B | 保持「实现不负责检测」 | 重叠调用是 UB，且判据无法写成运行断言 | 与 roadmap 的 FSR-16 冲突 |

## 裁定

选 **A**。重叠是公开 API 的 UB 脚枪，能用一个返回值消掉就不要留给调用方；B 让「重叠输入」变成无法二值判定的状态（判定原则 2）。

## 理由

1. 检测成本是常数级两次比较，不改变任何合法调用的结果（PH-01 九行表全部不变）。
2. 改成「拒绝」后判据可运行断言：`out == path` 时返回 -1 且 `out[0] == 0`，已在 `test/fsguard/r05_normalize.ct` 落地。
3. 保留 README 的「不要这样调用」说明：拒绝是防御，不是鼓励。

## 替换后的判据原文

> 4. `out` 与输入重叠（`out == path`，或 `out` 缓冲区落在输入字节范围内）时返回 -1 且 `out[0] == 0`；README 仍注明这是错误用法。

## 失效条件

`normalize_to` 改为返回新分配的缓冲区（不再由调用方提供 `out`）时，重叠检测自然消失，本裁定失效。

## 影响

R-05 判据 4 从「文档约束」转为「运行断言」；R-05 保持可验收。
