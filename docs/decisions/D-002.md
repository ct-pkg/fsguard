## 裁的是什么

Q-6：`_root` 是绝对路径时，`check("src/a.c")` 这类相对输入应当拒绝，还是按 root 解析成绝对路径再判定。

## 两案对比

| 案 | 行为 | 代价 | 与现有条款的关系 |
| --- | --- | --- | --- |
| A（推荐） | 绝对 root + 相对输入 → `FS_ERR_OUT_OF_BOUNDS`；`is_under` 只比较两个绝对字符串 | 调用方必须先转绝对；R-06 判据 1 的相对示例要改 | 保持「按段比较」的纯词法定义；R-09 判据 4 仍是纯词法 |
| B | 相对输入按 root 拼接并规范化后再判定；`src/a.c` 锚定为 `/root/src/a.c` | 需要 join + 规范化；要定义 `..` 逃逸；与 Q-3 耦合 | R-06 相对示例可保留为 1，但 `is_under` 不再是无隐式 base 的两字符串比较 |

## 裁定

选 **A**。冻结口径：

- `_root` 为绝对路径时，`check` 收到不以 `/` 开头的输入，直接返回 `FS_ERR_OUT_OF_BOUNDS`。
- `is_under(path, prefix)` 只按两个绝对路径的段边界比较；相对路径不锚定。
- `normalize_to` 仍可纯词法处理相对路径（保留前导 `..`），但相对结果不能直接喂给绝对 root 的 `check`。

## 理由

1. `is_under` 的定义是「按段边界比较两个路径字符串」；相对路径没有 base 时无法与绝对前缀做段比较，返 1 只能靠隐式锚定，等于偷偷改语义。
2. 拒绝相对输入是唯一不需要新增参数、也不依赖 Q-3 的方案；安全上也不会因为 CWD 或隐式拼接产生意外放行。
3. R-09 的判定顺序、错误码和纯词法性质保持不变；只把 Q-6 的建议从「当前建议：拒绝」冻结为「拒绝」。

## 代价

- 调用方必须先把相对路径转成绝对路径；`check("src/a.c")` 会失败，UX 变差。
- R-06 判据 1 的相对示例必须改；`is_under` 无法直接回答「相对路径是否在绝对前缀下」。

## 若选另一案会打破什么

选 B 必须给 `is_under` 增加一个隐式或显式 base：隐式 base 让「两个字符串比较」的定义失效；显式 base 会改公开签名。还要定义相对 `..` 是否可逃出 root（与 Q-3 耦合），并让 `check` 的 `last_error().path` 从相对变成绝对。R-06 的相对示例可以保留，但代价是三处语义同时变复杂。

## 判据

- `check("/workspace/src/a.c") == FS_OK`
- `check("src/a.c") == FS_ERR_OUT_OF_BOUNDS`
- `is_under("/workspace/src/a.c", "/workspace/src") == 1`
- `is_under("/workspace/src2/a.c", "/workspace/src") == 0`
- `is_under("src/a.c", "/workspace/src") == 0`

## 失效条件

- 后续要求支持相对输入且不引入 base 参数；或
- 后续同意给 `is_under` 增加显式 base，并接受 Q-3 的相对 `..` 规则。
