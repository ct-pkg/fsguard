## 裁的是什么

`check` 只做词法规范化与段边界/前缀/deny 判定，不访问文件系统。问题是：对外还能不能称它为「沙箱 / 安全边界」，以及要不要补 `lstat` / `realpath` / `openat` 去堵符号链接、TOCTOU、硬链接与挂载点。

## 裁定

选 **A**。边界写死如下，不留模糊空间：

- **`check` 是词法策略，不构成安全边界。** 它只比较规范化后的路径字符串，不建立任何隔离。
- **不在防护范围**：TOCTOU（`check` 与 `open` 分离，检查后被替换链接可绕过）、硬链接（不比较 inode / `nlink`）、挂载点与绑定挂载（不比较 `st_dev`）、超长路径的语义保证、符号链接环（只按 `errno` 归 `FS_ERR_IO`，不专门防护）。
- **不解析、不跟随符号链接**：不做 `realpath`，不做 `openat(O_NOFOLLOW)`；`read_file` / `read_chunk` / `write_file` 在词法检查后按原路径打开。`walk` 里的 `lstat` 只取条目类型（`is_dir`），不用于安全判定，也不跟随链接。
- **不新增防护原语**：不因为本裁定往包里加 `lstat` / `realpath` / `openat` 分支。
- **对外表述**：README、教程、需求、验收文档不得再以「沙箱」「安全边界」描述本包的能力；只能写「词法策略层」并列出未防护项。包名与 API 保持不变。

## 判据

1. `README.md` 含边界行「**这是词法策略层，不是安全边界；不解析符号链接、不防 TOCTOU。**」（可核对）。
2. `docs/requirements.md` 的 H-3、C-06、Q-1 均标「已裁（D-012）」并指向本文件（可核对）。
3. `docs/acceptance/fsguard-status.md` 含「H-3 / Q-1 已裁（D-012）」（可核对）。
4. 当前规范性文档（README、`docs/requirements.md`、`docs/acceptance/*`、`docs/fsguard-usage-tutorial.md`、`docs/fsguard-core-requirements.md`）不以「沙箱」描述本包能力；仅允许引用提案原文或历史评审（可核对，残留清单见 §影响）。
5. 实现不以 `realpath` / `openat` 做防护，`lstat` 只用于 `walk` 的条目类型（`grep -n 'realpath\|openat' src` 命中 0；`lstat` 只在 walker）（可核对）。
6. 未防护项在 README 或状态表中逐项可见：TOCTOU、硬链接、挂载点、超长路径、符号链接环（可核对）。

## 理由

1. **主张与实现必须一致**：`check` 是纯字符串比较，读写在检查后按原路径 `open`；把它叫沙箱就是虚假安全承诺。
2. **真沙箱会推翻现有契约**：`openat(O_NOFOLLOW)` 与 `realpath` 需要重做读写面，R-12 不能再复用 `std::fs` 的便捷写法，R-09 的「纯词法」判据也要改写。
3. **项目目标不是隔离**：本包补的是规范化、段边界、策略判定、错误码与遍历；隔离应由调用方的权限模型、容器或 `openat` 层解决。
4. **边界写死才能防止误用**：未防护项明文列出，比模糊的「沙箱」更可验收，也更难被下游当成权限边界。

## 失效条件

- 负责人要求「真沙箱」或出现不可信输入的多租户场景：重开本裁定，R-09 增加 `lstat` / `realpath` / `openat`，R-12 的读写面重做，夹具与威胁模型同步改。
- `std::fs` 或 CT 语言提供可复用的 `openat(O_NOFOLLOW)` 能力，且成本可接受：重新评估 A/B。
- 威胁模型新增必须拦截的项（例如硬链接逃逸成为验收要求）：本裁定的「不防护」清单需要逐项改判。
