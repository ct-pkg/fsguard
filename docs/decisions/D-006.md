## 裁的是什么

Q-2：`write_file` 写到一半失败时，目标文件保留半截、回滚，还是原子替换。

## 三案对比

| 案 | 行为 | 代价 | 与既有条款的关系 |
| --- | --- | --- | --- |
| A（推荐） | `open(O_TRUNC)` 原地写；失败保留已写入前缀，不回滚、不删除；失败后目标内容**未定义**，README 与判据明示 | 调用方要原子性得自己写临时路径再 rename | 与 R-12 非目标「不做原子写」一致 |
| B | 临时文件 + `rename` 原子替换 | 多一次 open/rename；权限位与 inode 变化；崩溃时残留临时文件 | **直接冲突 R-12 非目标「不做原子写（临时文件 + rename）」** |
| C | 失败时 best-effort `unlink` 目标 | `unlink` 自己也可能失败，仍留下「文件可能不存在」的不可判定状态 | 无条款冲突，但判据写不死（见理由 2） |

## 裁定

选 **A**。`write_file` 的保证只有两条：成功返回 `len` 且落盘字节完全相等；失败返回错误码，**不承诺目标文件内容**。调用方需要原子性时自行写临时路径再 `rename`。

## 理由

1. B 与 R-12 已冻结的非目标正面冲突；按「宁可改措辞保留语义」的原则，不应为了 Q-2 去砍掉一条明确的能力边界（MVP 不做原子写）。
2. C 把失败后的状态变成「目标可能被删、也可能没删」：`unlink` 失败时调用方没有任何手段区分，正是判定原则 1 要避免的「无法表达的状态」。
3. A 是唯一能被判据写死的方案：失败只断言错误码，不断言文件内容；成功断言 `len` 与逐字节相等；越界路径断言「目标不存在」因为 `check` 在 `open` 之前。
4. 代价（可能留半截文件）被显式写进文档与判据，不藏在实现里。

## 判据

1. `write_file` 成功返回 `len`，落盘字节与输入逐字节相等（含内嵌 NUL）。
2. 越界路径：返回 `FS_ERR_OUT_OF_BOUNDS`，且目标文件不存在（`check` 先于 `open`）。
3. 失败只断言错误码（`NOT_FOUND` / `PERMISSION` / `IS_DIR` / `IO`），**不断言目标文件内容**。
4. `docs/fsguard-usage-tutorial.md` 或 README 必须写明「失败后目标内容未定义，需要原子性请自行临时写 + rename」。

## 失效条件

出现以下任一情况需重开 Q-2：MVP 解除「不做原子写」非目标；或在 Linux 上出现调用方必须依赖失败后旧内容保留的真实用例。

## 影响

R-12 的判据 3 增加返回值断言；R-12 的失败路径从「半截文件是否保留」改为「只验错误码」；R-14 的文件操作以 `O_TRUNC` 打开。
