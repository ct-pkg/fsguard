## 裁的是什么

Q-7：deny pattern 的 glob 方言。MVP 是否接受「无 `**`、`*`/`?` 不跨 `/`、全路径匹配、目录命中跳整棵」。

## 三案对比

| 案 | 行为 | 代价 | 与现有条款的关系 |
| --- | --- | --- | --- |
| A（推荐） | `fnmatch` + `FNM_PATHNAME` 最小集：`*`/`?` 不跨 `/`；大小写敏感；按规范化全路径匹配；目录命中跳整棵；无 `**` | 不能写递归模式；用户按 gitignore 预期写 `**` 会失效 | 与 R-10 判据 3 逐字一致；`**` 已列 P2 |
| B | 支持 `**` 的完整 glob | 实现/测试面变大；要定义 `**` 跨段语义 | 超出 MVP；与 P2 排期冲突 |
| C | 只支持精确路径/段前缀，不做 `*`/`?` | 表达力最弱 | 直接砍掉 R-10 判据 3 要求的 `*`/`?` 能力 |

## 裁定

选 **A**。冻结 R-10 判据 3 的最小方言；`**` 仍留在 P2。

## 理由

1. R-10 判据 3 已经逐字写出最小方言；A 只是把它从「按 Q-7 建议」冻结为最终口径，不需要新增语义。
2. B 把 P2 的 `**` 提前到 MVP，扩大实现与测试面；C 砍掉 `*`/`?`，违反「宁可改措辞，不砍能力」。
3. `fnmatch` + `FNM_PATHNAME` 的行为可由 libc 判据写死；大小写敏感和全路径匹配都有唯一期望值。

## 代价

- 不支持 `**`，递归目录要写多条 pattern 或由调用方分层遍历。
- `*` 不跨 `/`；`/ws/secret/*.key` 不匹配 `/ws/secret/deep/a.key`，与 R-10 判据 3 一致。
- 大小写敏感在 APFS 默认大小写不敏感卷上仍是已知平台差异（CG-10），不由本裁定消除。
