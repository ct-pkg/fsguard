## 裁的是什么

R-11 判据 3 要求「保存第一次失败的 `e1->path` 字符串副本，触发第二次错误，断言旧指针内容已变（ASan 下无 UAF 读取）」。这条不是稳定后条件：`free` 之后旧指针的值不确定，内容可能原样保留；按判据去读它就是 UAF，而 ASan 会直接 abort。

## 两案对比

| 案 | 行为 | 代价 | 与既有条款的关系 |
| --- | --- | --- | --- |
| A（推荐） | 判据 3 改成三条可核对/可运行项：① README 写明 `last_error()` 及其 `path`/`message` 在下一次操作后失效、不得跨操作持有；② 每个公开操作开头调用同一个清错函数（可核对）；③ 运行断言「第二次失败后，当前 `last_error()` 只反映新错误」 | 不再声称「能证明旧指针失效」 | 保留「借用」语义，删掉不可判定的运行断言 |
| B | 保留原判据 | 判据永远红/不可判定，R-11 一直挂在「部分」 | 与「判据必须二值」冲突 |

## 裁定

选 **A**。旧指针的「内容已变」不是可观察契约；可观察的是「当前对象反映哪次错误」与「实现是否在每次操作开头释放旧值」。

## 判据

1. `README.md` 或 `docs/fsguard-usage-tutorial.md` 含失效条款（可核对：`grep -q '下一次'`）。
2. `src/fsguard/FsGuard.h.ct` 中所有公开操作（`check`/`read_file`/`write_file`/`read_chunk`/`walk`）都在开头调用 `fsg_error_clear`（可核对：计数）。
3. 运行：第一次失败 → 第二次失败后 `last_error()->code` 与第二次返回码一致、`path` 为第二次的规范化路径。
4. 测试与示例不得解引用跨操作的旧 `FsError *`（代码评审项）。

## 失效条件

CT 或 API 增加错误代次（generation）字段，可运行地判定「旧借用已失效」时，恢复运行断言。

## 影响

R-11 从「部分」转为「可验收」；判据 3 的运行断言从 `test/fsguard/r11_error.ct` 删除（已删），改为文档 + 清错路径核对。
